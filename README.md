# Elevé: Real Estate Platform for India

Buy or rent property across 10 major Indian cities using map-first search, AI matching, fair-price checks and rated agents.

## Run

```bash
npm install
npm start          # http://localhost:3000
npm run dev        # auto-restart on changes
npm run seed       # regenerate data/db.json (wipes reviews & enquiries)
```

### Turning on Claude

The AI features use Claude (`claude-opus-5-5`) when credentials are available:

```bash
# PowerShell
$env:ANTHROPIC_API_KEY = "sk-ant-..."
npm start
```

(An `ant auth login` profile also works.) At startup the server checks the credentials and logs either `[ai] Claude enabled` or `[ai] Using built-in AI fallbacks`.

Without credentials, every AI feature still works using built-in fallbacks: a keyword parser and rule-based summaries. The UI labels each result "Generated by Claude" or "offline mode", so users know which one they're seeing.

## AI features

These are features built into the normal search pages, not a chatbot.

| Feature | Where | How it works |
|---|---|---|
| **Describe it** | Home hero, refine bar on results | Plain English such as "2 BHK near Hinjewadi IT park, furnished, under 35k" is turned into structured criteria (Claude with structured JSON output). Landmarks are mapped to nearby localities. Results are **soft-matched and ranked** with a match % and ✓/✕ reasons. Each criterion appears as a chip you can remove. |
| **Price Check** | Every card, map popup and detail page | A fair-price model is fitted per city: `₹/sq ft = buy/rent baseline × locality factor × property-type factor`. The factors are fitted alternately with medians, so they hold up against outliers. The asking price is compared with the estimate to give one of four verdicts: Great deal, Fair, Slightly high, Overpriced. A gauge shows where the listing sits, with an estimated range and a confidence level. "Great deals" is available as a filter and "Best value" as a sort. |
| **AI Brief** | Property page | Shows why you'll like the property, what's worth checking, and questions to ask the agent. One click adds the questions to your enquiry message. |
| **What clients say** | Agent panel and profile | Summarises an agent's reviews into strengths, concerns and who the agent suits best. |

Claude results are cached in memory per property or agent. The cache refreshes when a new review is posted.

## Selling, transactions and settings

- **Sell your property** (`#/sell`): a 5-step verification flow enforced by the server. The user sees only "Step N of 5" and the current step; later steps can't be reached early, and earlier ones can be revisited.
  1. Phone verification with a one-time code. It expires after 5 minutes, allows 5 attempts and has a 30-second resend cooldown. There's no SMS gateway in the demo, so the code is shown on screen.
  2. Identity check by PAN. The format is validated, the 4th character must match the ownership type, and owners must be 18 or older. Only a masked PAN is stored.
  3. Property details, with a live suggested price range from the Price Check model and an optional suggested description.
  4. Ownership documents: PDF, JPG or PNG up to 5 MB. Each file is checked by its contents, not just its name, and saved privately under `data/uploads/` (never publicly served).
  5. Review, three declarations, and a verification fee of ₹499 including GST, paid with a **demo payment**: no money is charged and no payment details are collected.

  After submission the listing goes through a simulated review (20 s, set by `REVIEW_MS`) and is then published as a verified owner listing. The owner's phone number is shared only with people who enquire.
- **My listings** (`#/my-listings`): drafts with a Continue button, review progress, and live listings with views and a price verdict. Owners can pay ₹999 to feature a listing for 7 days.
- **Transactions** (`#/transactions`): summary totals, filters for payments, refunds and status, search, monthly grouping, a receipt panel with a downloadable receipt, and CSV export. A few sample transactions marked "Sample" are included for the demo.
- **☰ Menu and Settings** (`#/settings`):
  - Profile.
  - Account & verification.
  - Notifications: what to be notified about and through which channels. These choices are saved, but the demo doesn't send notifications.
  - Preferences: light, dark or system theme; text size; short or full price format; default city; the first tab on the home page; reduce motion. All of these take effect immediately.
  - Privacy & data: data-sharing switches, clearing saved homes, downloading your data as JSON, and deleting your account.
  - Payment methods: default method and saved UPI IDs.
  - Help (FAQ) and About.

The app has a single demo account (no login). Its profile, settings, listings and transactions are stored in `data/db.json`.

## Other features

- **Map-first browsing:** split list and map with price pins. Hovering a card highlights its pin, and clicking a pin opens a preview. On phones there's a Map/List toggle.
- **Agent panel:** tapping any agent's name opens a side panel (a bottom sheet on phones) with their full profile. It includes ratings and breakdown, reviews, RERA number, languages, areas, response time, listings, the AI summary, a call button and a message form.
- **Filters:** buy or rent, city, locality, budget, type, BHK, great deals, plus a "more filters" panel for furnishing, construction status, minimum area, must-have amenities and verified listings. All filters are kept in the URL, so searches can be shared and bookmarked.
- **Reviews:** users can rate and review agents. **Saved homes:** stored per browser.

## Structure

```
server.js          Express REST API + static hosting
lib/ai.js          Claude integration + offline fallbacks (search parsing, briefs, review summaries)
lib/insights.js    Price Check model and match scoring
data/seed.js       Deterministic generator for cities, coordinates, agents, properties, reviews
data/db.json       JSON data store (created on first run)
public/            Frontend SPA (vanilla JS, Leaflet map, no build step)
```

## API

| Method | Path | Notes |
|---|---|---|
| GET | `/api/meta` | Cities (coordinates, counts, avg ₹/sq ft), types, amenities, AI status |
| GET | `/api/properties` | Filters: `listingType, city, locality, propertyType, bhk, minPrice, maxPrice, minArea, furnishing, status, amenities, verified, deal, q, agentId, ids`. Also `match` (criteria JSON, for ranked soft matching), `sort` (`relevance, value, newest, priceAsc, priceDesc, areaDesc, popular`), `markers=1` (all map pins), and `page, limit`. |
| GET | `/api/properties/:id` | Full property with price insight, agent profile and similar listings |
| GET | `/api/agents` | `city, locality, specialization, language, minRating, verified, q, sort, page, limit` |
| GET | `/api/agents/:id` | Profile, reviews, listings |
| POST | `/api/agents/:id/reviews` | `{ author, rating (1-5), comment }` |
| POST | `/api/enquiries` | `{ agentId or propertyId, name, phone, email?, message?, wantsVisit? }` |
| POST | `/api/ai/search` | `{ query }` returns structured criteria plus a summary |
| GET | `/api/ai/property-brief/:id` | AI brief for one listing |
| GET | `/api/ai/agent-summary/:id` | AI review summary for one agent |

## Next steps for production

The JSON file store is fine for a demo. Before going live, you would need:

- A real database, such as PostgreSQL with PostGIS for map search.
- User accounts, so owners and agents can post their own listings and reviews can be verified.
- Image uploads.
- SMS or WhatsApp alerts for enquiries.
- Price Check retrained on real transaction data.
- Rate limits on the `/api/ai/*` endpoints.
